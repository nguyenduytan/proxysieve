# Optional HTTPS Inspect

HTTPS Inspect is an advanced module for explicitly selected CONNECT hosts. It is
off by default. Normal CONNECT and every SOCKS5 connection remain opaque tunnels.

## Create and trust the local CA

Stop ProxySieve before changing the CA, then use the same config file used by the
gateway:

```sh
proxysieve inspect ca init --file config.yaml
proxysieve inspect ca fingerprint --file config.yaml
proxysieve inspect ca export --file config.yaml --path proxysieve-inspect-ca.crt
```

Install only the exported certificate in the dedicated browser, automation profile
or client trust store that should use Inspect. Never trust it system-wide unless
that broader scope is intentional. Verify its SHA-256 fingerprint before import.

The certificate and private key are stored together at
`<data_dir>/inspect/ca.pem`. The file is restricted to the current account and
Local System on Windows, and mode `0600` on Unix. The private key is never printed
or included in `inspect ca export`, portable config export or backup documentation.

Rotate with `inspect ca rotate`; export and install the new certificate, then
restart ProxySieve. Rotation invalidates certificates generated by the previous CA.

## Configuration

```yaml
inspect:
  enabled: true
  include:
    - "*.example.com"
  exclude:
    - "accounts.example.com"
  on_failure: reject
```

Exclude rules win over include rules. Patterns are exact hosts or a leading `*.`
wildcard. The gateway refuses to start with Inspect enabled until a valid,
restrictively protected CA exists.

`on_failure: reject` fails closed when a leaf certificate cannot be prepared.
`on_failure: tunnel` may use the normal tunnel only when setup fails before the
CONNECT response is sent. Certificate pinning or a client rejecting the local CA
happens after interception starts and always closes the connection; ProxySieve does
not silently downgrade that connection to a tunnel. Put pinned hosts in `exclude`.

## Visibility and privacy

Inspected HTTP/1.1 requests use the same policy evaluator, router, budgets, cache,
shadow comparison and traffic accounting as visible HTTP traffic. Method, HTTPS
URL/path, sanitized request/response headers, response status, content type and
application-stream sizes appear in the bounded process-local System view.

Query values are always redacted. Header values are retained only when
`logging.capture_headers: true`; authorization, cookies, tokens, credentials and
similar fields remain redacted. Observations are limited to the newest 1,000 entries
and are not persisted. Request and response bodies are never captured, decompressed
or logged by Inspect.

The inner Host must match the CONNECT authority. Nested CONNECT, HTTP/2, HTTP/3,
QUIC, WebSocket upgrades and pinned clients are not inspected. The module advertises
HTTP/1.1 through ALPN and rejects unsupported behavior without bypassing the
configured route or destination controls.
